Operating Fact

Read the facts at their source.
Don’t infer what the system can tell you.

WORLDLINE asks the components that own the facts. It reads native desktop and system interfaces, then returns structured observations with source, time, validity, and revision attached. No screenshot reconstruction. No invented certainty. No hidden provenance.

The operating picture / 16 observation sections

A machine is more than
the screen it shows you.

WORLDLINE reads across the host, its resources, the desktop session, connected interfaces, running work, and the tools available to that environment. These are distinct observation domains in one revisioned snapshot — not a geometry feature with extras.

All this info in an instant.

01 / Power & thermal

The machine's energy state.

AC connection and online state, battery charge status and percentage, remaining energy, current power draw, voltage, cycle count, estimated time to empty or full, and available thermal-zone readings.

02 / Host & hardware

What the machine is.

Hostname, machine and boot identity, architecture, vendor, model, board and BIOS details, GPU devices and drivers, virtualization, and container context.

03 / Operating system

The software foundation.

Distribution and release, codename, kernel, architecture, libc and version, Python runtime, and locale.

04 / Processor

CPU capacity & activity.

Processor model and vendor, sockets, physical and logical cores, current and min/max frequency, load averages, runnable or blocked tasks, and context switches.

05 / Memory

Working capacity.

Total, used, free and available memory, buffers, cache, dirty pages, swap capacity and use, and utilization percentages.

06 / Resource pressure

When resources are contested.

Kernel pressure-stall information for CPU, memory, and I/O — including some and full pressure windows where the kernel exposes them.

07 / Storage

Filesystems & capacity.

Local mount targets, backing sources, filesystem types and options, total, used, free and available space, and utilization.

08 / Network

Connectivity & traffic.

Interfaces, link state, addresses, MAC and MTU, wireless presence, byte and packet counters, errors and drops, routes, default gateway, DNS, and listening sockets.

09 / Processes

Work happening now.

Process identity, parentage, state, resource use, and a bounded view of the busiest processes; command-line credentials are redacted before export.

10 / Desktop & displays

The graphical environment.

Session type and desktop, compositor identity, screen bounds, logical monitors, connector relationships, resolution, scale, transform, primary display, and refresh rate.

11 / Windows & accessibility

Applications as interfaces.

Window and application identity, title, role, accessible component extents, focus and active state, visibility, minimization, maximization, modal state, and compositor-verified frames and stacking where available.

12 / Session

The user's active environment.

Session and seat identifiers, user and process context, TTY, display endpoints, runtime and D-Bus locations, SSH/root context, and selected environment values.

13 / Audio

Sound I/O state.

Audio server, default output and input devices, output volume, and mute state when the audio provider is available.

14 / Working context

Where the work is rooted.

Current directory, writability, filesystem device and inode, Git root, branch, HEAD commit, and detached state when inside a repository.

15 / Available tools

What the environment can run.

Presence and executable paths for a broad catalogue of system, desktop, development, media, automation, and browser tools.

16 / Time

A shared temporal reference.

Epoch time, millisecond timestamp, local ISO timestamp, timezone, and UTC offset.

Evidence across every section

Every fact has a context.

Observation source, collection time, freshness and expiry, availability, and revision. Consumers can request fresh samples, compare revisions, wait for changes, and record receipts against a shared observation state.

A deliberate boundary

WORLDLINE observes.
It does not act.

No input injection. No window activation. No action policy. WORLDLINE provides a read-only observation surface across the machine’s exposed operating context; consuming systems retain responsibility for decisions and actuation.

Get started

Give your tools a better view.

WORLDLINE targets Ubuntu with GNOME on Wayland. Install the managed user service to give agents a structured view of desktop, application, and system context.

sudo apt install git python3 python3-venv python3-pyatspi libglib2.0-bin zip
git clone https://github.com/ryanraposo/WORLDLINE.git
cd WORLDLINE
./scripts/worldline-install.sh install
./scripts/worldline-install.sh status

The installer asks before enabling the read-only GNOME Shell frame extension. Review the permission before approving it. WORLDLINE does not send input or activate windows.
